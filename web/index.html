AI is the engine

Every “AI role” cell in the brief is a real model call with a per-call receipt logging model, purpose, prompt size, latency, HTTP status and parse result — not a template with slots. Deterministic maths validates the model instead of silently replacing it: the Tukey outlier fence, the weighted engagement score, the funnel, the movement windows and the ICP rule table all compute the same quantities independently, and every disagreement is written to the receipt and printed on the dashboard rather than hidden. Where a model call fails, the module says so — M1 degrades that batch to the rule table with a stated reason, M2 and M3 fail the run rather than ship stale copy.

M1

Enrichment

Four reasoning jobs, each checked or capped by the rule engine.

Gray-zone dedupe adjudication — pairs scoring [0.65, 0.80) go to the model with both records; capped at 20 pairs a run, every decision recorded. The committed slice caught one such pair, within-batch, and the model ruled no merge with a written rationale; the live HubSpot-side search logged matches: 0, gray_zone_pairs: 0, so no CRM-side pair reached the model in that run.

Row inference — title, function, seniority for the rows the rule cascade could not resolve.

Firmographics — industry from the ICP vocabulary plus an employee-count estimate and a confidence, batched per distinct company.

ICP tier + rationale — the rule formula recomputes the tier; a disagreement of more than one level ships flagged for a human, not silently overwritten. That is the capability, not this receipt's result: all three ICP batches came back unusable, so icp_rows_scored_by_llm: 0 and icp_rows_rules_fallback: 32 — every tier in the committed slice is the rule table's, and the file records it rather than passing rules off as model output.

M3

Repurposing

Extraction → per-asset generation → grounding gate → deterministic cuts.

Extraction returns clip-worthy moments, insights, quotes and data points; every timestamp is snapped onto a real transcript turn and every speaker corrected to whoever the transcript shows, so asset prompts never see ungrounded material.

Four asset generations run off that verified extraction, each spec-checked before it is written; the blog's word gate regenerates once and then fails the run.

Grounding verifier re-checks every timestamp, quote and attribution afterwards — 39 of 39 verified on the committed run, across youtube.md, infographic.md and social.md; blog.md recorded 0 claims checked in that report. Clips are ffmpeg; captions come from Sarvam's own word timings.

Real vs simulated

Real

  • The event, its public page, its recording and both speakers.
  • The transcript — a real Sarvam batch STT run over the real chapter audio, three jobs, receipt on disk.
  • Every generated artifact — blog, chapters, infographic, social posts, email copy, dedupe adjudications, ICP rationales, dashboard analysis — is the output of a real model call with a per-call receipt.
  • The HubSpot calls: dedupe searches, contact/company/association writes, property and lifecycle updates, and the portal read-back.

Generated or simulated — labelled everywhere it appears

  • The registrant list is generated. Real companies, real domains, real HR roles, real regions — invented people. No shareable attendee list exists for this webinar, so none was used.
  • M4's engagement stream is seeded into a HubSpot developer test portal by the seed phase and carries source: "seeded" in the receipt, in the snapshot, in each movement window's source mix and on the dashboard badge. Every lifecycle transition in that portal was written by this pipeline — 39 of the 40 on 2026-09-21 and one older, per dashboard_data.json's window dates — and the dashboard says so in its first sentence.
  • Images: 0 of 3. Image generation returned HTTP 402 on an unfunded key; the receipt records the model, the status and the error, and no placeholder image was written in their place.
  • The live lane runs mostly, not entirely, on free-tier OpenRouter models. M1, M3 and M4's committed runs used nvidia/nemotron-3-super-120b-a12b:free and its fallback chain, which is why some calls show provider 502/429 retries. M2's committed run did not — all four calls ran on google/gemini-2.5-flash-lite, a paid model, for roughly half a US cent.
  • Speaker addresses are not public, so speaker mail is addressed to sender-controlled aliases; the event page publishes no air date, so event.json.date is a disclosed assumption.
