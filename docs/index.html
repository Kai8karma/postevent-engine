Kshitij Mishra — AI-Led Post-Event Content Automation

Built for the assignment: turn a webinar's raw exhaust — recording, transcript, registrant list, engagement data — into HubSpot-ready leads, sent comms, repurposed content, and a live dashboard, with AI doing the actual work at every step, not wrapping a manual process.

Thesis: AI does the actual reasoning work in this build, but not identically across modules, and we'd rather show you the real shape of that than round it up. M1 runs a deterministic rules lane offline (dedupe + field inference by lookup table, zero LLM tokens) and switches to real LLM classification with --live; M2 and M3 ship genuinely LLM-generated copy, replayed from a fingerprint-guarded cache offline so the demo doesn't need an API key; M4 computes its metrics directly from data and calls a live LLM only for the narrative summary, falling back to a labeled cached one without a key. Humans approve every send either way.

The four modules

Each is independent and separately demoable. Judge-facing path: ./demo.sh --live — chains M1→M2→M3→M4 with real LLM calls into out/<event-slug>/ and prints a stage/seconds/key-output/pass-fail receipt. ./demo.sh without the flag (or the module scripts below, run individually) is the instant preview — same DAG, cached/deterministic outputs, zero network calls, zero wait.

M1

Lead List Enrichment

Fuzzy-dedupes the 150-row messy Zoom export against existing HubSpot contacts (difflib, no fuzzy-matching library needed), infers missing title/seniority/company size/industry, scores ICP tier with a written rationale per row, assigns region, and routes ownership — same-day SDR-handoff-ready. Offline default is a deterministic rules lane (lookup tables, no LLM tokens spent); --live swaps in real LLM field classification.

./demo.sh --live
Instant preview (deterministic rules, no LLM)
python3 modules/m1-enrichment/enrich.py --out out/m1
Key output
hubspot_ready.csv — contact + company completeness ≥90%, ICP tier + rationale, region, owner, lifecycle stage per row
Outputs: offline run → Outputs: live LLM run → Module README →
M2

Post-Event Communications

Drafts three segment-specific email variants (attendee thank-you, no-show catch-up, speaker thank-you), two subject-line options each, personalized off the enriched contact list and the real transcript — then holds at a human-approval gate before anything is logged to HubSpot with UTM tracking. No blind sends. The copy is genuinely LLM-generated either way; offline replays a fingerprint-guarded cache instead of re-calling the model.

Run (judges — live)

Outputs: offline run → Outputs: live LLM run → Module README →
M3

Content Repurposing

Extracts the quotable moments, data points, and structure straight from the ~8k-word transcript and generates a full multi-format package: one 800–1200-word blog draft, YouTube chapter markers + description + thumbnail brief, an infographic outline, and 5–10 social posts across LinkedIn and X, each with a distinct hook. LLM-generated either way; offline replays a fingerprint-guarded cache instead of re-calling the model.

M4

Lead Intelligence Dashboard

Reads M1's enriched roster plus engagement events (opens, clicks, page views, form fills) and computes the attendee→MQL funnel, top engaged accounts and buying committees, and 7/14/30-day lifecycle movement — all real math over the data, not LLM output. The one narrative summary line is a live LLM call on Vercel, with a clearly labeled cached fallback when there's no key.

What the free model taught the code, all fixed in this build and kept: reasoning-style models (we tried stealth/ox-alpha first) wrap JSON in fences and append a sentence after the closing fence, spend their whole completion budget thinking on a long transcript, and take ~2 min a call — so every module now extracts the first complete JSON value rather than trusting the whole response, sizes timeouts/max_tokens for it, retries a non-JSON answer, validates the shape against the renderer's contract before persisting anything, and OPENROUTER_MODEL accepts a comma-separated fallback chain for when a free provider is overloaded (it was, twice).

Swap to your real event

Everything above ran on a synthetic-but-realistic stand-in webinar because your real event wasn't named before the deadline — the pipeline itself doesn't know the difference. Swapping in your actual webinar is two edits: drop your registrant export, transcript, and speaker/event metadata into data/incoming/, and point config/icp.yaml at your real ICP tiers, regions, and owner routing. No code changes, no re-architecture.

That means we can point this at your next webinar Monday morning — same four modules, same human-approval gate before any send, same dashboard — and have enriched leads, drafted comms, a repurposed content package, and a live lead-intelligence view ready before your SDR team finishes their coffee.
